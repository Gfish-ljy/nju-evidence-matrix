## 1. 统一约定

### 1.1 ID

- 所有对象使用字符串 ID，永不复用，跨对象引用只用 ID。
- 格式：`P0001`（论文）、`C0001`（Claim）、`CD0001`（Condition）、`E0001`（Evidence）、`R0001`（Relation）、`K01`（Cluster）、`U0001`（Update）。
- `Claim.status` 是当前状态快照；状态历史以 `knowledge_states` 最新版本为准。

### 1.2 命名与格式

- JSON 字段：`snake_case`；枚举值：`PascalCase`；文件名：`snake_case`。
- 时间：ISO 8601 UTC，如 `2026-11-20T10:00:00Z`；日期：`YYYY-MM-DD`。
- 字符串统一 UTF-8；数组无数据用 `[]`，未知标量用 `null`，不省略字段。
- 枚举一律英文常量，中文显示由 UI 的映射表负责（见第 3 节）。

### 1.3 响应壳

所有接口统一返回：

```json
{"data": {}, "meta": {"page": 1, "size": 20, "total": 50}, "error": null}
```

失败时 `data` 为 `null`，`error` 为：

```json
{"code": "NOT_FOUND", "message": "claim C0001 not found", "details": {}}
```

错误码：`INVALID_PARAM` / `NOT_FOUND` / `CONFLICT` / `UNSUPPORTED` / `INTERNAL`。

### 1.4 分页与排序

- `page` 从 1 开始，默认 1；`size` 默认 20，最大 100。
- 排序参数 `sort=field:asc|desc`，默认按 `id` 升序。
- 列表接口必须返回 `meta.total`。

### 1.5 API 版本

- 路径前缀：`/api/v0/`。
- 破坏性变更升版本（v1），不兼容字段变更必须走评审。

### 1.6 mock 与真实数据

- UI 通过配置切换 mock / 真实 API，接口形状完全一致。
- mock 数据必须能通过 `docs/schema_v0.json` 校验。

## 2. 数据对象

### 2.1 Paper

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| paper_id | string | 是 | 主键 |
| title | string | 是 | 标题 |
| authors | string[] | 否 | 作者列表 |
| year | int | 是 | 发表年份 |
| venue | string | 否 | 会议/期刊 |
| doi | string | 否 | DOI |
| url | string | 否 | 论文链接 |
| pdf_path | string | 否 | 仓库内相对路径 |
| citation_count | int | 否 | 引用数，默认 0 |
| quality_score | float | 否 | 0–1，质量评分 |
| is_selected | bool | 是 | 是否进入 50 篇精选集 |
| selection_reason | string | 否 | 入选理由 |

### 2.2 Claim

## 3. 枚举与中文映射

### 3.1 Relation.type

| 值 | 中文 | 说明 |
|---|---|---|
| Supports | 支持 | 提供支持另一结论的证据 |
| Contradicts | 冲突 | 在可比条件下结论不一致 |
| Extends | 扩展 | 扩展到新任务/场景 |
| Refines | 细化 | 进一步明确或细化 |
| Qualifies | 限定 | 仅在特定条件下成立 |
| Supersedes | 替代 | 在特定范围内取代原结论 |

### 3.2 KnowledgeState.state

| 值 | 中文 | 说明 |
|---|---|---|
| Supported | 有证据支持 | 现有证据总体支持 |
| Contested | 存在冲突 | 存在相互冲突的证据 |
| Qualified | 条件受限 | 结论只在特定条件下成立 |
| WeaklySupported | 弱支持 | 支持证据较少或较弱 |
| Superseded | 已被取代 | 被后续研究在范围内取代 |
| Unresolved | 未决 | 证据不足以判断 |

### 3.3 Evidence.stance

| 值 | 中文 |
|---|---|
| Support | 支持 |
| Contrast | 对比/反驳 |
| Background | 背景 |
| Method | 方法 |

### 3.4 Relation.condition_comparability

| 值 | 中文 |
|---|---|
| Comparable | 可比 |
| Partial | 部分可比 |
| Incomparable | 不可比 |

### 3.5 Review.status

| 值 | 中文 |
|---|---|
| Pending | 待审 |
| Accepted | 通过 |
| Rejected | 驳回 |
| Edited | 已修改 |

## 4. 数据文件

| 文件 | 内容 | 格式 |
|---|---|---|
| `paper_nodes.json` | Paper 数组 | JSON 数组 |
| `paper_edges.csv` | source_paper_id, target_paper_id, citation_context, section, stance, confidence | UTF-8 CSV，带表头 |
| `claims.json` | Claim 数组 | JSON 数组 |
| `conditions.json` | Condition 数组 | JSON 数组 |
| `claim_edges.json` | Relation 数组 | JSON 数组 |
| `evidence.json` | Evidence 数组 | JSON 数组 |
| `clusters.json` | Cluster 数组 | JSON 数组 |
| `knowledge_states.json` | KnowledgeState 数组 | JSON 数组 |
| `updates.json` | UpdateLog 数组 | JSON 数组 |

示例：

```json
// claims.json
{"claim_id": "C0001", "paper_id": "P0001", "problem": "...", "method": "...", "condition_id": "CD0001", "finding": "...", "evidence_ids": ["E0001"], "status": "Unresolved", "cluster_id": "K01", "created_at": "2026-11-20T10:00:00Z"}
```

```json
// claim_edges.json
{"relation_id": "R0001", "source_claim_id": "C0001", "target_claim_id": "C0002", "type": "Contradicts", "confidence": 0.82, "evidence_ids": ["E0001", "E0002"], "condition_comparability": "Partial"}
```

## 5. API 契约（v0）

| 方法 | 路径 | 用途 | 关键参数 |
|---|---|---|---|
| GET | `/api/v0/papers` | 论文列表 | query, year, venue, selected, page, size, sort |
| GET | `/api/v0/papers/{paper_id}` | 论文详情 | — |
| GET | `/api/v0/claims` | Claim 列表 | paper_id, cluster_id, state, page, size |
| GET | `/api/v0/claims/{claim_id}` | Claim 详情 | — |
| GET | `/api/v0/claims/{claim_id}/evidence` | 证据列表 | stance |
| GET | `/api/v0/relations` | 关系查询 | source_claim_id, target_claim_id, type |
| GET | `/api/v0/clusters` | 簇列表 | level |
| GET | `/api/v0/graph` | 图数据 | level=paper\|claim\|cluster, time_window |
| GET | `/api/v0/matrix` | 证据矩阵 | row=claim\|cluster, col=method\|dataset\|condition\|metric |
| GET | `/api/v0/knowledge-states` | 状态历史 | claim_id |
| GET | `/api/v0/updates` | 更新日志 | claim_id |
| POST | `/api/v0/review/claims/{claim_id}` | 人工校验回写 | body: state, relation_id, comment |

### 5.1 `/graph` 响应

```json
{"data": {"nodes": [{"id": "K01", "type": "cluster", "label": "Memory retrieval", "state": "Contested", "size": 12, "position": [0, 0, 0]}],
         "edges": [{"id": "R0001", "source": "C0001", "target": "C0002", "type": "Contradicts", "weight": 0.82}]},
 "meta": {}, "error": null}
```

### 5.2 `/matrix` 响应

```json
{"data": {"rows": [{"id": "C0001", "label": "..."}],
         "cols": [{"id": "method:retrieval", "label": "Retrieval"}],
         "cells": [{"row_id": "C0001", "col_id": "method:retrieval", "counts": {"Supports": 2, "Contradicts": 1}, "state": "Contested", "evidence_count": 3}]},
 "meta": {}, "error": null}
```

### 5.3 `/claims/{id}/evidence` 响应

```json
{"data": [{"evidence_id": "E0001", "paper_id": "P0001", "section": "Results", "page": 7, "quote": "...", "stance": "Support"}],
 "meta": {"page": 1, "size": 20, "total": 1}, "error": null}
```

## 6. UI 数据需求

| 层级 | 页面职责 | 需要的数据 | 依赖接口 |
|---|---|---|---|
| L0 总览 | 展示问题簇、规模、知识状态、争议比例 | 簇节点、聚合边、状态分布、证据量、时间范围 | `/graph?level=cluster`、`/clusters` |
| L1 簇内 | 展示 Claim 与六类关系 | Claim 节点、关系边、年份、证据数 | `/graph?level=claim`、`/relations` |
| L2 矩阵 | 对比多 Claim 的条件与关系 | 行列维度、单元格计数、条件可比性 | `/matrix` |
| L3 证据 | 原文、条件、版本、校验 | 论文元数据、Claim、Condition、Evidence、UpdateLog | `/claims/{id}`、`/claims/{id}/evidence`、`/knowledge-states`、`/updates` |

UI 文档必须引用本节的字段与枚举，不再单独定义一套。
